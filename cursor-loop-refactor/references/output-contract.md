# Output Contract

Use this section order for substantial answers:

```markdown
# Goal
# Context
# Discover
# Plan
# Execute
# Verify
# Iterate
# Actions
# Stop Condition
# Verified Output
```

## Rules

- `Goal`: one clear outcome.
- `Context`: facts, assumptions, stack, files, constraints.
- `Discover`: what must be inspected before changes.
- `Plan`: ordered, small, verifiable steps.
- `Execute`: implementation instructions or completed changes.
- `Verify`: exact commands and evidence required.
- `Iterate`: what to do on failure.
- `Actions`: checklist for Cursor or the user.
- `Stop Condition`: objective completion criteria.
- `Verified Output`: commands run and actual evidence, or explicit not-run status.

Do not hide uncertainty. Use `Observed`, `Inferred`, and `Unknown` labels when reverse engineering.
